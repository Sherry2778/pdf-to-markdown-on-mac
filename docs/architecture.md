# 设计说明

## 一份文档的处理路径

```text
选择或拖入 PDF
  → 去重并加入队列
  → 为当前文件启动独立子进程
  → 验证文件与识别无文字图片页
  → 调用 MarkItDown 的 PDF 转换器
  → 完整写入临时文件
  → 原子创建新文件名，遇到重名自动递增编号
  → 将结构化结果返回界面
  → 显示状态并处理下一份文件
```

## 主要选择

### 独立进程

GUI 使用 Qt 的 QProcess 启动转换组件，避免耗时解析阻塞界面。
每份文件使用独立进程，一份失败不会终止整个批次。

取消时先发送终止信号，给 Python 清理临时文件的机会；
若子进程在 2.5 秒内没有结束，再结束该进程。
强制结束可能遗留隐藏的临时文件，已发布的 Markdown 是完整文件。

这种方式有每份文件的启动开销，优先满足取消操作和错误隔离。

### 明确的 PDF 转换路径

应用直接调用固定版本 MarkItDown 的 PDF 转换器。
它不接受网页 URL，也不启用其他格式转换器、远程模型或外部插件。
保留 MarkItDown 作为依赖，避免将它的转换算法宣称为项目原创。

### 结果协议

子进程输出一条 JSON，包含是否成功、输出路径、页数、字符数、
耗时和警告信息。原始文档正文不通过这个协议返回。
GUI 在用户选择结果后，从本地文件读取预览。

### 不覆盖已有文件

先将完整结果写到目标目录中的临时文件，写入成功后通过硬链接
以排他方式发布为最终文件名。重名时尝试下一个编号。
发布和清理之间，最终文件仍然引用已经写完的数据。

目标磁盘不支持硬链接时会提示改用本地文件夹。

### 内容核对

没有提取到文字时明确报错，不把空文件当作成功。
检测无文字的图片页并给出提示；这只是遗漏风险提示，
不能证明其他页的识别和阅读顺序完全正确。

## 由本项目实现的部分

- 中文桌面工作流和批量队列。
- 子进程管理、取消、恢复与错误提示。
- 去重导入、同名保护、结果预览和全文复制。
- 独立应用构建、许可收集、合成测试和项目文档。

PDF 内容提取来自 MarkItDown，GUI 组件来自 PySide6/Qt。
代码实现使用了 AI 辅助。
